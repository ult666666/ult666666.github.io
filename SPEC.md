# Charles Dai’s portfolio

## Purpose

Give a classmate a way to try something Charles built and give an engineering reviewer a way to check how it works. Update Charles’s existing GitHub Pages portfolio using its public projects and studio contact. Charles delegated the final design and editorial decisions to Codex on November 27, 2026.

| Project | Story the homepage should tell | What the visitor can do |
| --- | --- | --- |

## Structure and interaction

- Open with Charles’s name, his studies at Carnegie Mellon and the kind of work he does. Let the visitor jump directly to any of the five featured projects.
- List all 21 public projects in the homepage index with an outcome, the tools used and a relevant next step. Include the Snowfall OS sample village and the JUST-QR generator. Describe Teen Budgeting as coursework using fictional expenses.
- Make the explorer searchable by words and focus area. Keep project names, outcomes, tools and primary links easy to scan. Put longer technical walkthroughs behind a keyboard-operable disclosure. Project entries and links should work with JavaScript turned off.
- Use About to show how Charles checks the results of his work. Use his published studio email for contact.
- Retain the existing serif typography, warm paper background, blue links and original project screenshots. The navigation, tables and project links must be usable on a narrow phone.

## Delivery

Publish the reviewed files to the existing GitHub Pages site. Include this specification and the prompt log in the source repository. Verify that the deployed homepage, the public repository and project navigation work for a signed-out visitor.
