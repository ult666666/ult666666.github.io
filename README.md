# Charles Dai: portfolio site

[![Portfolio checks](https://github.com/ult666666/ult666666.github.io/actions/workflows/portfolio.yml/badge.svg)](https://github.com/ult666666/ult666666.github.io/actions/workflows/portfolio.yml)

Source for **[ult666666.github.io](https://ult666666.github.io/)**: five featured projects, a one-line index of all 21, six case studies, two pages of walkthroughs and a searchable [project explorer](https://ult666666.github.io/projects/catalog.html).

Plain HTML and CSS with system fonts and screenshots from the projects. No web fonts, analytics, cookies or third-party requests. Only the explorer uses JavaScript, for search, and every page works without it. The [site spec](SPEC.md) and [prompt log](PROMPTS.md) cover the November 27 revisions; [DESIGN.md](docs/DESIGN.md) covers the look.

## Run it

Python 3.11+ and Node.js 22+.

```sh
python3 -m http.server 4319 --bind 127.0.0.1   # browse at http://127.0.0.1:4319
python3 -B -m unittest discover -s tests -v
npm ci --ignore-scripts --no-audit --no-fund
npx playwright install chromium
rm -rf _site && npm run build
PORTFOLIO_TEST_ROOT=_site npm run test:browser
python3 -B scripts/build_site.py --verify _site
```

`npm run build` checks that generated pages are current, then stages the public files in `_site`. It won't overwrite an existing `_site`. The browser tests accept `PLAYWRIGHT_MODULE`, `PORTFOLIO_CHROMIUM_EXECUTABLE` and `PORTFOLIO_CHROMIUM_ARGS` (a JSON array); none of them affects the published site. `scripts/check_github_headings.py` checks that links into project docs still land on real headings (needs a signed-in GitHub CLI).

| Page | Source |

After editing a case study or the catalog data, regenerate with `python3 -B scripts/build_cases.py` and `python3 -B scripts/build_catalog.py`. The build and tests reject stale generated HTML.

## Publishing

`public-files.json` lists every file that may be published. `scripts/build_site.py` copies only those into `_site`, refuses anything unlisted, linked or oversized, and writes a SHA-256 manifest it checks afterwards. CI runs the tests on every pull request and deploys `main` to GitHub Pages only when they pass. [PUBLICATION_BOUNDARY.md](docs/PUBLICATION_BOUNDARY.md) explains why; report security issues as described in [SECURITY.md](SECURITY.md).

[`examples/operations_handoff/`](examples/operations_handoff/README.md) installs released RelayBox, TraceBench and Impact Ledger wheels offline and runs one synthetic webhook through all three. The `handoff.yml` workflow runs it; its reports stay out of the site.

## Limits

- These are portfolio projects built with AI coding assistants. The finance and data demos use synthetic data. MOTIONX is the public website for my studio.
- Financial figures on the fintech page and in the Frontier case study are illustrative, not valuations or investment advice. The trading research project can’t place orders and is not evidence of returns.
- The publication check keeps unlisted files off the site. It is not a secret scanner; anything committed here is public.
- The site links to documented work only: no invented employers, clients or usage numbers.
