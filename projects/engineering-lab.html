01 Backend reliability

RelayBox

A signed webhook inbox with a durable SQLite job lifecycle. Delivery IDs deduplicate matching payloads, conflicting reuses are rejected, and expiring leases let a new worker recover interrupted work.

A fencing token prevents an old worker from acknowledging a job after another worker has reclaimed it.

03 Full-stack operations analytics

Impact Ledger

A nonprofit reporting workbench with a typed frontend, a Python API and a SQLite store. Filter synthetic program records, distinguish unique participants from attendance, and compare session spending with budget.

Sessions and attendance have separate grains, so a busy event does not multiply its own expenses. Imports validate before committing, and accessible tables keep the numbers available alongside the charts.

One installed handoff

From one webhook to one report

This AI-assisted educational drill connects the three released tools through real local HTTP services. Fictional English/Mandarin names, including Alex Chen / 陈安, make the synthetic fixtures readable; the ledger imports participant IDs.

  1. Accept a signed event. RelayBox persists the delivery, deduplicates an identical replay and rejects a changed one.
  2. Keep the receipt. A bounded worker writes canonical receipts; an explicit adapter extracts their sessions and attendance CSV bytes.
  3. Preview, then import. Impact Ledger's advisory preview changes no rows and reserves no IDs. A separate explicit import revalidates and commits atomically.
  4. Compare exact totals. The selected program and inclusive dates fix the population. Costs count each session once; people count distinct IDs.
  5. Check the recorded contract. TraceBench checks nine recorded JSON contracts, with no provider calls.

The receipt effect, CSV import and inbox acknowledgment are separate transactions. They do not guarantee exactly-once processing across systems.
