02 / ENGINEERING APPROACH

Thoughtful by design.

01 — BUILD◇

Start with the human.

Make the purpose clear. Design the interaction around an actual task. Reduce complexity at the surface without hiding it under the hood.

02 — VERIFY⊕

Show the evidence.

Prefer reproducible tests, source links and explicit constraints. A meaningful failure report is more useful than an unearned green checkmark.

03 — REFINE↗

Iterate with intention.

Improve the visuals, the system boundaries and the developer experience together. Document what changed and why it matters.

INSPECT THE IMPLEMENTATION

Three claims. Three places to check.

Go beyond a screenshot: read the method, the code and the tests behind the work.

01 / FINANCIAL CORRECTNESSCheck the arithmetic.

Follow the shared browser/API calculations and the separate Python reference. Consistent calculations are not a promise about forecasts.

Inspect valuation verification ↗ 02 / INPUT CONTRACTSUnderstand what gets refused.

Review schema-change validation, downstream impact analysis and the boundary between a migration proposal and execution.

Read the engineering review ↗ 03 / RELEASE ENGINEERINGPublish the site. Not the workspace.

Inspect the exact public-file inventory, negative-case tests and byte-checked release. Private files do not belong in a public demo.
